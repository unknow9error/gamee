## Автоматические проверки

```sh
flutter analyze
flutter test
```

Набор проверяет правила пяти механик, реальные жесты, неправильные действия, восстановление после перезапуска, сбой записи и повторную попытку, резервную копию, доступ к главам, повторные награды, настройки, языки, родительскую защиту, поворот, маленькие экраны и геометрию иллюстраций.

`test/widget_test.dart` проверяет весь `PlayScreen`, а не только изолированный виджет: маленький холст считается ошибкой даже при отсутствии Flutter overflow.

`test/visual_smoke_test.dart` загружает настоящие встроенные шрифты, проходит обучение, карту и все механики; после рисования меняет ориентацию и выходит с сохранением. Получить рендеры из исходников:

```sh
flutter test test/visual_smoke_test.dart --dart-define=CAPTURE_FIXTURES=true
```

`output/qa/fixture-*.png` — рендеры Flutter test. Файлы с префиксами `android-` и `ios-` — отдельные снимки нативных запусков. Рендеры из исходников не доказывают работу платформенных плагинов.

## Нативный сценарий

Обычный запуск на настроенной машине:

```sh
flutter test integration_test/app_test.dart -d DEVICE_ID
```

Также имеется `test_driver/integration_test.dart` для Flutter Drive. Сценарий проходит пять первых упражнений жестами через полный UI, получает 15 звёзд и четыре рисунка, проверяет открытие главы и загружает прогресс новым контроллером из настоящего платформенного хранилища. Данные изолированы в пространстве `integration.*`: обычное сохранение ребёнка не сбрасывается. Проверяется регистрация нативного речевого канала; наличие установленного голоса не предполагается.

На этой машине общий поиск устройств Flutter зависал в служебных обёртках Xcode, ожидавших `xcodebuild -runFirstLaunch` из-за разных версий CoreSimulator. Был изменён способ запуска проверки: тот же self-driven test target собран напрямую и установлен через ADB / штатный vendor simctl. Тестовый фреймворк сам записывает `tiny-trails-qa-result.json` в `Directory.systemTemp` только после выполнения своих assertions и завершения suite. На Android это каталог `code_cache` тестового приложения, на iOS — `tmp` его контейнера. Эти синтетические итоговые файлы скопированы в QA-отчёты. Оба содержат passed=true.

Для Android такой target собирается командой:

```sh
flutter build apk --debug --target=integration_test/app_test.dart --target-platform android-arm64
```

Для iOS:

```sh
flutter build ios --simulator --debug --target=integration_test/app_test.dart
```

Этот target является тестовым harness. Его нельзя выдавать за обычный установщик. Итоговые `output/Tiny-Trails-Android.apk` и `output/Tiny-Trails-iOS-unsigned.zip` содержат обычное приложение с entry point `lib/main.dart`; после тестов обычные приложения восстановлены в эмуляторах.

## Установочные артефакты

- `output/Tiny-Trails-Android.apk`: оптимизированный ARM64 предпросмотр со стандартной тестовой подписью Android; подпись проверена `apksigner verify` и установка проверена в эмуляторе.
- `output/Tiny-Trails-Android-debug.apk`: универсальная debug-сборка для дополнительной разработки.
- `output/Tiny-Trails-Android-arm64-unsigned.apk`: оптимизированная сборка без подписи владельца.
- `output/Tiny-Trails-iOS-unsigned.zip`: неподписанный device Runner.app; для физического iPhone требуется подпись Apple Developer команды владельца.
- `output/Tiny-Trails-Source.zip`: исходники, тесты и документация; локальные конфигурации и build caches исключены.

Release по умолчанию не подписывается. Только явный `ORG_GRADLE_PROJECT_tinyTrailsPreview=true` включает стандартную тестовую подпись для локального Android-предпросмотра. Production-ключи и приватные конфигурации проектом не создавались и не просматривались.

## Границы проверки

Это результаты эмулятора/симулятора и автоматических тестов. На физических iPhone, Android и планшете ещё нужна оценка пальцем и стилусом, длительной сессии, звука, установленных голосов и читаемости с детьми целевой возрастной группы. Эмулятор Android запускался без звука на хосте, поэтому слышимость мелодий и озвучки не проверена человеком.

Публикация в App Store/Google Play, магазинные метаданные, production-подписи и внешняя пользовательская приёмка не выполнялись. Педагогическая эффективность исследованиями не подтверждалась.
